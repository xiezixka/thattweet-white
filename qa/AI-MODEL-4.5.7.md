# 4.5.7 AI 模型校验修复

日期：2026 年 11 月 14 日。

## 故障依据

用户提供的新版错误截图显示批量 AI 分析返回 HTTP 400，服务端指出传入的模型名为空，并列出了该次响应支持的模型名。该错误说明请求抵达了服务端，但不能据此证明密钥完全有效、任意模型可用或其他功能都正常。

源码原先允许空 model 发送到 chat/completions；自动分析队列也没有在标记 Processing 前检查模型和节点启用状态。另外，模型列表的异步回调会用旧的完整设置覆盖当前设置，存在撤销新模型选择的风险；不能由截图确定当时是否触发此竞态。

## 修复

- 请求适配器校验模型、API Key 和接口地址，缺失时在本地报出可读配置错误，不发请求。
- 自动队列在未配置模型、未配置服务商或节点禁用时跳过，保留待处理记录，不将它们误标为失败。
- 模型列表响应基于最新设置更新缓存；服务商删除或凭据变化时丢弃旧响应，保留新选模型。
- 按明确的 HTTP 状态判断重试；400 错误中的 request_id 包含数字 50 不再被误当作 5xx。429 和 5xx 保持可重试。
- 工作流显示未选模型提示，并明确：服务商可继承默认，模型必须单独选择；手动输入模型名须按 Enter 确认。
- 不自动选择付费模型，不自动重跑历史失败记录，不操作原版或两版用户数据目录。

## 验收

- 类型检查、12 项回归测试通过。
- 重点覆盖：空模型 0 次 fetch；有效模型准确发送并解析响应；空模型/禁用节点不读取或改写待处理推文；HTTP 400 与 429/500 区分；延迟模型列表不覆盖新选择。
- 独立 localhost 页面使用模拟扩展 API 和示例数据测试：初始 5 个未选模型提示，选择一个模型后变成 4 个；实际输入另一个模型名时，按 Enter 前存储仍保留旧选择，按 Enter 后保存新选择。无页面脚本错误。
- Chrome/Firefox 构建、清单引用资源与 ZIP 完整性通过。校验值见 evidence/build-validation-4.5.7.json；界面截图见 evidence/model-required-4.5.7.png。
- 样式机械检查保留了一处原有灰字/彩色背景提示，本次没有进行整体界面重设计。

## 使用与尚未验收部分

更新程序文件后，需要在 Chrome 对现有白色版重新加载。到「实验室 → 神经中枢 → AI 工作流 → 快速分析」选取账户支持的模型；从下拉列表点选，或手动输入后按 Enter。其他要使用的节点也需单独选模型。

旧错误日志不会自动消失。先用一条纯文本推文的手动分析验证新请求，历史失败记录不由本修复自动重跑。该次服务端模型名来自截图，不作为永久或通用于所有服务商的硬编码列表。

真实 AI 调用未验收：没有读取用户密钥，也没有用真实账号调用服务商。聊天、笔记及完整数据迁移仍未完成，继续保留原版。
